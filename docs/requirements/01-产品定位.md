## 产品定位

- **一句话**：把需求从想法管到上线，AI 干重活、你只做决定。
- **定位**：SaaS 需求管理平台，核心是「AI 辅助、人机可替换」的需求全生命周期流水线。从一句初始需求到拆分出的开发任务，全过程由人、Agent 或人机协作完成，且可随时切换。

## 目标用户

- **核心用户：一人公司**。定义：**1 个人（老板）或几个员工的有限公司——是完整注册、完整运营的正式公司**，不是个人开发者的业余项目。它有人少、组织扁平、没有专职 PM/QA/运维、一个人戴多顶帽子的特点，但有真实业务、要对外交付、管理要正规化。
- **扩展用户：中小开发团队**（几十人，有专职产品/开发的团队）。他们的痛点不是「没人管」，而是「流程效率」——同样受益于 AI 辅助和 agent 员工。

### 核心用户的一天（场景）

**现状（没有工具时）**：
- 老板/创始人从客户或自己脑子里接到一个需求，随手记在聊天记录或脑子里。
- 没有专职 PM：需求为什么提、边界是什么、做成什么样，过两周就模糊了。
- 任务靠口头拆解，排期靠拍脑袋，进度靠问。
- 文档、任务、代码、上线各管各的，对不上账。

**用了这个平台之后**：
- 把一句「我想提升研发效能 100%」丢进去，AI 产品经理开始追问澄清，产出需求文档。
- AI 评估价值、写 PRD、组织评审质询、拆任务，人只在关键节点做裁决（档位确认、评审通过、验收、发布）。
- 迭代内的开发任务由 **AI agent 员工** 认领执行（对一人公司，agent 是主力员工，不是辅助），人的精力只花在决定上。
- 任务上线 = 发布成功 = 需求完成，一切自动汇总，老板打开 Dashboard 就能看到进展。

### 为什么不用现有工具

- **大厂工具太重**：Jira / 禅道 流程繁琐、配置复杂、字段学不完——为一个只有几个人的公司不值得。
- **项目管理工具只管「任务」这一段**：Linear / 飞书多维表格等管不了「需求从哪来、为什么做、做到什么程度算完」，需求前段（澄清/评估/评审）靠人肉，也不闭环到「上线」。
- **主流工具不把 AI agent 当员工**：没有一套让 agent 认领任务、产出文档、走流程、接受验收的机制——而这是核心用户最需要的。

### 核心价值主张

1. **AI 辅助**：AI 承担访谈挖掘、文档/PRD 生成、评审质询、任务拆分、分派与装填等重活，人只做裁决与把关。
2. **人机可替换**：流水线每个环节的处理人均为「人 / Agent / 人机协作」三选一，团队模板统一配置，单需求可覆盖——**让 AI agent 真正当员工干活，而不只是聊天工具**。
3. **全生命周期闭环**：需求按「初始需求 → 产品需求 → 系统需求 → 任务」三层树分解，贯穿澄清、价值评估、PRD、评审、拆分、迭代交付、发布上线。

### 一人多角是常态（设计前提）

对核心用户，同一个人往往身兼多职：既是提出人（接需求），也是产品经理（做裁决），还可能是架构师（主持技术评审）、测试人员（执行测试）与开发人员（开发执行）。AI agent 则承担其余重活（澄清、评估计算、PRD、质询、拆分、开发/测试执行）。这套「人做关键裁决、agent 干重活」的配合，正是整个产品「人机可替换」设计的出发点。
