> 按业务域分组组织功能，便于后续模块划分。每个叶子功能标注：描述、验收标准、里程碑、是否涉及 AI、依赖。**叶子功能共 89 项**（v0.7 新增 TE-12 空间管理、TE-13 空间内角色权限维护、IT-10 迭代发布；v0.9 新增 VE-01 版本管理、VE-02 需求归属版本；**v0.10 无叶子功能增删，仍 89 项**；**v0.12 任务双类型（开发任务 / 测试任务）用现有 TA/IT 系列表达，不新增叶子，仍 89 项**；**v0.13 需求验收状态机、验收不通过返工、待验收提醒按优先级、提出人线上验收，均用现有 RE/NT 系列表达，不新增叶子，仍 89 项**）。

## 4.1 域 A：租户与团队

**域目标**：租户隔离、账号认证、空间（租户下的需求集目的容器）与成员（含 Agent）建模、空间内角色权限、流水线处理人配置。

**分支展开**：
```
租户与空间
├─ 租户与账号
│  ├─ TE-01 租户注册与创建
│  ├─ TE-02 租户数据隔离
│  ├─ TE-03 租户内成员管理
│  ├─ TE-11 账号认证与登录
├─ 空间管理
│  ├─ TE-12 空间管理（创建/负责人设定）
│  ├─ TE-13 空间内角色权限维护
│  ├─ TE-05 团队管理
│  ├─ TE-06 团队成员管理
│  ├─ TE-07 成员角色/技能/容量建模
│  ├─ TE-04 角色权限（基础）
│  └─ TE-08 内置 Agent 目录
└─ 流水线处理人配置
   ├─ TE-09 团队级处理人模板
   └─ TE-10 单需求处理人覆盖
```

## 4.2 域 B：需求

**域目标**：三层需求树（初始需求 / 产品需求 / 系统需求）的管理、各层独立的状态流转、需求树与进度汇总、就绪度、全局标记、直接创建来源、流水线编排与分层产物管理、**版本规划（v0.9，v0.12 补交付判定/废弃移出版本/挂起留版本/归版本由产品经理决定）**。

**分支展开**：
```
需求
├─ 需求对象
│  ├─ RE-01 需求创建（分类型 + 树 + 直接创建来源）
│  ├─ RE-02 需求列表/检索/筛选
│  ├─ RE-03 需求详情与编辑（含需求树视图）
│  ├─ RE-04 需求删除（二次确认）
│  └─ RE-14 需求附件管理
├─ 版本规划
│  ├─ VE-01 版本管理（创建/状态/交付日期）
│  └─ VE-02 需求归属版本（单选）+ 版本页聚合视图
├─ 分层状态流转
│  ├─ RE-05 分层状态流转（按类型）
│  ├─ RE-06 环节流转动作（含分解校验）
│  └─ RE-07 处理人解析（按环节）
├─ 澄清环节（L1）
│  ├─ RE-08 AI grill 式访谈
│  ├─ RE-09 访谈记录与人工补充
│  ├─ RE-10 需求文档生成
│  └─ RE-11 需求文档人工修订与确认
├─ PRD 环节（L2）
│  ├─ RE-12 PRD 生成
│  └─ RE-13 PRD 修订与版本
├─ 需求树与进度
│  ├─ RE-15 需求树管理（父子关系）
│  ├─ RE-16 进度自动汇总
│  └─ RE-17 就绪度与可开发筛选
└─ 全局标记
   └─ RE-18 全局标记（挂起/阻塞，不沿树传递）
```

**叶子功能表：**

| 编号 | 叶子功能 | 功能描述 | 验收标准 | 里程碑 | 涉及AI | 依赖 |
|---|---|---|---|---|---|---|
| RE-01 | 需求创建（分类型 + 树 + 直接创建来源） | 创建初始需求 / 产品需求 / 系统需求，指定类型与父级；**L3 系统需求按业务领域拆分（高内聚低耦合，一个 L3 = 一个业务领域，领域边界 = 技术侧上下文边界/DDD 限界上下文落地，v0.10）**；规模自适应：中小需求可跳过初始需求层直接创建产品/系统需求。**直接创建来源（v0.6，v0.11 修订评审必走）**：产品需求可由产品经理直接创建（自身规划类，跳过访谈澄清与 L1 评估，但 L2 评估 + 评审仍走，PM 自行产出需求文档）；系统需求可由架构师/研发直接创建（技术改进/技术债类，跳过评估/PRD/评审，但 L3 的设计 → 技术评审必走（可轻量，不跳过，v0.11），需求带「技术改进，未走业务评估」标记）。 | 可创建三类需求；产品/系统需求可指定父级；无父级的初始需求 = 根需求；直接创建的产品/系统需求可独立存在；技术改进类系统需求带标记；直接创建的产品需求 L2 评估 + 评审仍走；技术改进类直建系统需求的设计 → 技术评审必走（可轻量）；L3 系统需求体现按业务领域拆分（一个 L3 = 一个业务领域）。 | M0 | 否 | - |
| RE-02 | 需求列表/检索/筛选 | 按类型/父级/状态/档位/优先级/提出人/关键字筛选，分页。 | 各筛选组合生效；可查看某父级下全部子级；列表展示类型与状态标签。 | M0 | 否 | RE-01 |
| RE-03 | 需求详情与编辑（含需求树视图） | 查看需求全貌（本层产物只读展示）、需求树视图（父/子级）、编辑基础字段。 | 基础字段可编辑；需求树视图展示父子关系与各层完成情况；AI 产物非草稿态只读。 | M0 | 否 | RE-01, RE-15 |
| RE-04 | 需求删除（二次确认） | 删除（物理删除、二次确认）；**去归档（v0.7）**——不再有「归档」概念，不做但需留档用「挂起」、终止用「废弃」。 | 删除父级前校验子级（提示先处理子级）；删除后关联任务提示失效；删除需二次确认。 | M0 | 否 | RE-01 |
| RE-05 | 分层状态流转（按类型） | 四层各自独立的状态流转，**含验收段（v0.13）**：L1 新建→澄清中→已澄清→**评估中→已评估**→进行中→完成→待验收→已验收；L2 新建→评估中→已评估→PRD→评审中→已通过→进行中→完成→待验收→已验收；L3 新建→设计→评审→进行中→完成→待验收→已验收；**任务按类型分流（v0.12）**：开发任务 6 态（待处理→进行中→**待测试**→待验收→待发布→已完成）+ 废弃第 6 态 + 测试打回/验收打回；测试任务 4 态（待处理→进行中→**待执行**→已完成，不发布、不验收）+ 需求废弃级联废弃。**需求层无「待发布」、中间态统一「进行中」（v0.10）**；任务层保留「待发布」（仅开发任务）。**验收口径（v0.13）**：需求「完成」= 开发活动彻底结束（全部直接子级已完成，进度 100%）→ 自动进入「待验收」→ 产品经理 + 提出人并行验收、对齐敲定 →「已验收」（终态）；验收不通过 → 回「进行中」返工重走；验收段不改变进度；待验收提醒按优先级（P0=1天/P1=2天/P2=3天/P3=7天）。**完成统一口径（v0.8，v0.12 补）**：开发任务「已完成」= 发布成功、测试任务「已完成」= 执行用例 + 三方确认；中间态不叫完成。记录流转历史。 | 各类型状态按定义流转；需求状态机含验收段（完成→待验收→已验收）；开发/测试任务各自状态机、可按类型筛选；跨类型分解校验直接子级已完成才置父级完成；测试不通过开发任务回「进行中」、验收不通过回「进行中」且返工后必须重新测试；需求废弃级联其下开发/测试任务废弃、恢复回最初状态；每次流转记录 操作人/时间/处理人模式；支持回退。 | M0 | 否 | RE-01 |
| RE-06 | 环节流转动作（含分解校验） | 驱动需求按本层的流程状态流转，校验当前阶段产物完整性；分解动作校验子级完成情况。 | 产物不完整时拦截并提示缺失项；**父级置「完成」需所有直接子级已完成**；可人工强制回退。 | M0 | 否 | RE-05 |
| RE-07 | 处理人解析（按环节） | 结合团队模板 + 需求覆盖，解析当前环节处理人与协作模式。 | 正确输出 人/Agent/人机协作；覆盖优先于模板。 | M1 | 是 | TE-09, TE-10, RE-06 |
| RE-08 | AI grill 式访谈 | AI 依据需求对提出人做多轮追问（目标/边界/例外/非功能/成功标准），挖出完整全貌（L1 澄清）。 | 至少产出 1 轮追问且基于需求上下文；能连续追问；产出结构化澄清纪要。 | M1 | 是 | RE-01, AI-01 |
| RE-09 | 访谈记录与人工补充 | 问答记录持久化；人可追加回答、改写任一问答。 | 记录可回看；人工补充内容纳入后续生成上下文。 | M1 | 是 | RE-08 |
| RE-10 | 需求文档生成 | AI 基于澄清结果生成结构化需求文档（背景/目标/用户/范围/非功能）。 | 文档含既定章节；内容与澄清问答一致；支持引用原始问答。 | M1 | 是 | RE-09 |

| RE-13 | PRD 修订与版本 | 人修订 PRD，保留版本历史；**评审打回后按修订指引修订并重新定稿**。 | 每次定稿生成版本号，可回溯任意版本。 | M1 | 否 | RE-12 |
