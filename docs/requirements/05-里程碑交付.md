**v0.7 变更说明**：新增 TE-12（空间管理）、TE-13（空间内角色权限维护）、IT-10（迭代发布，人工发布在 M0、CI/CD 自动发布扩展在 M2）；RE-04 去归档；完成口径改为「发布成功 = 任务完成」（需求完成 = 全部直接子级已完成，v0.13 起验收段不改变此口径；后改名「开发完成」）。
**v0.8 变更说明**：任务状态机改 **5 态（待处理→进行中→待验收→待发布→已完成）+ 废弃（当时称「第 6 态」，本次定稿修订统一称「废弃（终止态）」）**；「待发布」= 测试通过后、发布前；发布单**属于迭代**（迭代内可多个，随做随发），发布单关闭 → 范围内任务自动「已完成」；需求完成 = 全部任务已完成（系统自动判定；后改名「开发完成」）；需求废弃级联其下任务废弃、废弃恢复回最初状态（**本次定稿修订改为回废弃前状态快照，M6**）。
**v0.9 变更说明**：新增 VE-01（版本管理）、VE-02（需求归属版本 + 版本页聚合）；**版本 = 规划维度**（需求归入版本、单选、带规划交付日期），与迭代无直接绑定；**角色 = 权限打包的虚拟对象**，分人类角色与 Agent 角色两类，成员（人/Agent）被赋角色获得权限。
**v0.10 变更说明**：需求层（L1/L2/L3）去掉「待发布」态，全部直接子级已完成（发布成功）→ 系统直接判「完成」（后改名「开发完成」）；需求层中间态统一为「进行中」（原实施中/开发中）；L1 新增评估环节（评估业务目标值不值得做 → 做/不做（废弃）门槛，与 L2 的 S/M/L 档位评估是两套语义）；L3 按业务领域拆分（高内聚低耦合，一个 L3 = 一个业务领域，DDD 限界上下文落地）；已装入发布单的任务被挂起/废弃 → 自动移出发布单，发布单只发「仍为待发布」的任务；缺陷管理列入第二部规划（第一部不实现）。叶子功能数不变（仍 89 项）。
**v0.11 变更说明**：①验收打回累计 3 次 → 强制升人工（与评审对齐，产品经理/空间负责人介入）；②技术改进类直建 L3 的设计 → 技术评审**必走**（可轻量，不跳过）；③退化完成规则：废弃子级不计入父级完成判定，全部子级废弃时父级无法自动完成、提示人工处理（父级废弃 / 保留重拆）；④「待装填池」定名为 **backlog（待排期需求池）** = 已确认但未排期的需求（L2/L3）+ 任务的集合（业务上叫池子、实现是筛选视图）；⑤L1 评估复用 EV-01~04（不新增叶子）；⑥缺陷管理 = 第二部（第一部不实现，确认沿用）。叶子功能数不变（仍 89 项）。
**v0.12 变更说明**：①**任务双类型**：开发任务 6 态 + 废弃（待处理→进行中→待测试→待验收→待发布→已完成）、测试任务 4 态（待处理→进行中→待执行→已完成，不发布不验收）；「待测试」仅属开发任务、「待执行」仅属测试任务；L3 拆分同时拆两类任务（开发任务由开发人员/架构师基于系统设计拆、测试任务由测试人员基于 UI 设计 + PRD 操作流程 + 接口拆）；②**测试环节**：测试计划/用例/报告 = 本期流程占位（概念存在不实现存储），三方确认（产品经理+架构师+测试人员）、测试打回累计 3 次升架构师、验收打回返工后必须重新测试、发布单只装「测试通过+验收通过」的开发任务；测试任务跟随需求进迭代、独立估时、分派测试角色、计入团队负载；③**角色体系重构**：人类角色 7 类（空间负责人/产品经理/架构师/迭代负责人/开发人员/测试人员/UI设计师），取消「评审主持人」（L2 产品经理主持、L3 架构师主持）与「验收负责人」（验收归产品经理），Agent 目录 12 类（新增测试 Agent）；提出人为成员属性（可见自己提的需求状态/进度/完成，不可见迭代/任务/成员）；④**版本模型补充**：已交付 = 版本下所有需求已完成（系统判定；**本次定稿修订：改为「已交付 = 版本下所有需求均已『已验收』」，挂起/阻塞/进行中/开发完成/待验收 一律计未交付，验收段为交付判定必经环节**）、需求废弃自动移出版本、恢复不回版本、挂起留在版本、需求可不归版本（未归 = backlog）、父级归版本子级跟随/移出整棵子树移出、归版本由产品经理决定、规划交付日期为参考；⑤**UI 设计**：PRD 定稿后即启动（不等评审通过），UI 设计师（必须角色）产出设计稿/交互原型挂 L2、作为 L3 设计输入；⑥**改名**：「产品负责人」统一改「产品经理」（人），「产品经理 Agent」不变。叶子功能数不变（仍 89 项）。
**v0.13 变更说明**：①**需求验收状态机**：需求状态机加验收段「…→进行中→**完成**→**待验收**→**已验收**」（本次定稿修订：需求层状态「完成」统一改名为「开发完成」，任务层「已完成」不变）；「完成」= 开发活动彻底结束（全部直接子级已完成，进度 100%，状态与进度一致）；「待验收」= 完成即自动进入、通知产品经理 + 提出人**并行验收**（功能已上线双方都能看到）；「已验收」= 双方**对齐敲定**（终态）；验收段不改变进度；②**验收不通过 → 返工重走**：产品经理打回 / 提出人异议经评估 → 需求回「进行中」返工，按流程重走再验收（本次定稿修订补执行路径：挂「返工」待办 → 人工确认拆返工任务 → 开发/测试/验收/发布 → 再回开发完成 → 再入待验收；需求级验收打回累计 3 次强制升人工）；③**待验收提醒按优先级**：进入即通知，逾期按优先级催办（P0=1天/P1=2天/P2=3天/P3=7天，映射可配置 NT-02），直到验收敲定停止（本次定稿修订补：父级回落「进行中」时提醒同步停止）；④**提出人线上验收**：提出人验收他提的整棵需求（提 L1 就 L1 完成后触发、L2 就 L2，以此类推），非具体任务、后置确认不阻塞完成（本次定稿修订补：提出人整树线上验收只在其提出层执行一次，子级验收由产品经理业务裁决）。
**v0.13 本次定稿修订（六角色评审 grilling 回填，2026-08-12）**：①**验收单交互载体（B1）**：待验收→已验收以需求验收单承载（功能清单/验收项/上线链接/通过·异议/单内对话，留痕=对齐记录，挂需求详情不新增页面）；②**提出人可见性 = 权限并集（B2）**：提出人基线 ∪ 空间角色权限，角色授予只增不减；③**已验收守卫（B3）**：父级「已验收」= 全部直接子级均已「已验收」，真终态不可回落，版本「已交付」天然不可逆；④**强制人工 = 旁路标记（B4）**：评审/验收打回累计 3 次挂「强制人工」标记、状态机不变、AI 不代行、处理通过后解除；⑤**走查补挂起解除走通全流程（M1，§3.4.2 步 15b）**；⑥**待办/决策队列入 M0（M4，NT-04）**、**进入待验收最小站内通知入 M0（M5，红点/待验收清单高亮）**；⑦**废弃恢复 = 快照回滚（M6）**：回废弃前状态快照，已废弃子级保持废弃可单独恢复、已完成任务保持已完成；⑧**催办锚点 = 进入待验收时刻（M9）**：第 0 天即通知、每 N 天催办、无动作满 3 轮升级空间负责人；⑨**纠错回退（M10）**：产品经理/空间负责人（权限 TE-04）强制回退到指定合法前置态，必填原因、不计打回计数、不触发升人工；**常规纠错回退仅作用于非终态（需求「已验收」、任务「已完成」除外），终态误设走空间负责人「数据修正」（高权限 + 二次确认 + 留痕，独立于常规回退）**；⑩**UI 设计 = L2 正式产物硬输入（M12）**：评审打回 → PRD 修订 → UI 联动修订，存储挂 RE-14 附件；⑪**新增叶子 RE-19 需求验收单、NT-04 我的待办/决策队列，总数 89 → 91**。
